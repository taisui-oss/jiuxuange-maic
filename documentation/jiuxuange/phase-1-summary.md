# 第一阶段总结

## 1. 阶段目标

把 OpenMAIC 已验证的任务卡、PBL 状态机、多 Agent、互动节点、证据回放保留下来，改造成九轩阁商业模式大课的一条统一、持续、可断点恢复的学习会话。

本阶段重点不是完成六门课，也不是建立正式评分后台，而是验证以下垂直假设：

> 版本化课程包能否生成一个 PBL 项目，并在同一对话里用单问、证据门和角色调度持续推进学习。

## 2. 已完成

### 产品体验

- 首页提供一轮真实问题导学，并把导学草稿幂等附着到正式课程会话。
- 课程入口统一为“开始学习 / 继续学习 / 回看学习”。
- 点击课程后直接进入沉浸式课程对话工作台，不再要求学员操作外层播放控件。
- 学员不手动选择 A-J 节点；当前节点和下一问由系统状态决定。
- 教授、学长、神秘角色、成长反馈官作为同一学习线程里的可见人格，而非四个独立聊天室。

### 课程与案例

- 建立 `1.0.0-pilot-b` 与 `2.0.0-guided-course` 两个版本化课程包。
- V2 包含七个概念节点、便利蜂案例、生鲜零售比较案例和六道开放题。
- 概念资料按权威层级确定性检索；私有知识目录使用 `server-only`。
- 案例采用 `blind -> commit -> unlock -> compare`，提交独立判断前不开放作者分析。
- 正式数字评分保持关闭，学员只接收文字反馈。

### 运行与数据

- `scene.content.projectV2` 作为当前学习状态真相。
- 会话使用 `learnerId + courseId + projectId + packageVersion` 稳定组合键定位。
- 保存导学状态、当前 milestone/microtask、消息、运行事件、证据判断和测评回答。
- 建立单问约束、事实可见性、事实核验、教练结论隔离和答案泄露防线。
- LLM 网络异常时，九轩阁课程退化为本地确定性下一问，不再把技术错误直接暴露给学员。
- 非 ASCII 模型凭据会在进入 SDK 前被拒绝，修复 ByteString 错误。

### 工程资产

- 相对统一学习前的回退点，累计修改 84 个文件，新增约 7,807 行、删除约 297 行。
- 形成 20 个按 TDD 切分的实现提交。
- 建立 3 个回退分支。
- 当前阶段回归基线：30 个测试文件、267 个测试全部通过。

## 3. 已通过真实试用发现并修复

| 现象 | 根因 | 当前处理 |
|---|---|---|
| 中文 API key 占位值触发 ByteString 错误 | 非 ASCII 字符被写入 HTTP header | 凭据前置校验，PBL 路由使用有效提供方 |
| 进入课程后停在外层播放界面 | 九轩阁仍继承通用课堂 Hero/播放壳 | 九轩阁项目默认直接展开工作台 |
| 教授重复同一个问题 | 导学短回答不推进，规范化器强制回退到标准问句 | 增加上下文追问、重复投诉恢复和本地降级 |
| DeepSeek 超时导致学习中断 | 重试后直接暴露底层错误 | 九轩阁回合不做长重试，失败后使用确定性下一问 |
| 连续回答“不知道”仍原样追问 | 状态机只判断答案长度，没有教学支架 | 增加选择式支架和临时目标提议 |

这些修复证明真实回放比静态架构评审更能暴露学习产品问题，也说明 Prompt 不是可靠的业务状态机。

## 4. 尚未完成

### P0：开放用户前必须完成

- 服务端账号与花名身份，不再使用浏览器随机本地 ID。
- 服务端学习会话与事件账本，不再只依赖 IndexedDB。
- 学员、项目、小组和课程包的可审计绑定。
- 真实商业模式教材逐节核验、案例事实包审校、作者分析解锁规则审校。
- 导学短回答与提议接受语义。例如系统问“愿意先用这个目标开始吗”，当前“可以”仍会被公式化答案规则拒绝。
- 请求幂等、并发写入和断网恢复的服务端保证。
- 管理员最小后台：学习状态、异常、证据卡、人工复核入口。
- API key 完全服务端托管；浏览器不得继续传递供应商密钥。

### P1：进入正式试点前完成

- 有效学习时长事件模型与防刷规则。
- 真实项目事实导入、来源核验和版本冻结。
- 人工金标准校准集、AI 草评偏差阈值和复核流程。
- 学员个人反馈报告与证据回链。
- 试点回放自动沉淀为回归样本。

### P2：规模化前完成

- 小组协作、成员贡献归属与项目共识版本。
- 六门大课的课程包生产和审校流水线。
- 教练效率、认知密度、矛盾自主发现时延等 AI 原生指标。
- 数据权限、删除、导出、留存和隐私策略。

## 5. 当前最大的逻辑断层

1. **身份断层**：本地 learnerId 无法成为业务上的花名身份。
2. **数据断层**：浏览器项目状态无法支撑后台、跨设备和长期归档。
3. **内容断层**：课程节点存在，但教材片段尚不是完整、逐节审校的教学知识包。
4. **教学断层**：当前证据识别主要依赖长度、正则和事实文本重叠，尚不能稳定判断思考质量。
5. **评价断层**：六道题可以保存和反馈，但人工金标准不足，不能形成正式个人评分。
6. **运营断层**：异常尚未汇总给教练，教练仍无法只看高价值证据卡。
7. **发布语义断层**：代码里的 `full` 与业务里的“可正式开放”不是同一概念。

## 6. 阶段结论

这个阶段应该被定义为：

> **统一学习运行时原型完成，真实教学闭环尚未完成。**

下一阶段的成功标准不应是“再多做几个页面或角色”，而应是让 5-10 名真实学员在一个核验案例上走完：导学、概念、盲解、反证、迁移、测评、反馈，并能由教练从后台复核全部关键证据。
