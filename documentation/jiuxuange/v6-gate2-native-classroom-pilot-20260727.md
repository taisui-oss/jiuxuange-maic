## 1. 当轮试学定义（历史）

[KNOWN, HIGH] 当轮试学曾包含三个彼此分离的入口：

```text
六要素学习主线
→ OpenMAIC 原生多场景课堂

正式案例课
→ 按主线完成状态逐级解锁
→ 每个案例都是独立、预生成、多轮的 OpenMAIC 原生课堂

项目练习
→ 项目卡上下文讨论与个人项目测试
→ 不承担概念讲授
```

[DECIDED, HIGH] 便利蜂是正式案例课的形态标准。后续生鲜零售、SHEIN、花西子、
整车货运平台和智能汽车只有同时满足下列条件，才允许开放：

1. 形成独立课程包和稳定课堂 ID；
2. 包含连续的多轮场景，而不是单张案例卡或单轮聊天；
3. 使用 OpenMAIC 原生课件、角色讲解、互动和知识检测；
4. 完成具名 SME 教学审校；
5. 通过桌面、移动端、恢复和直接访问权限验收。

旧 V5/V5.1 固定问题、弱回答判断、补救教学和三态证据仍保留为实验资产，
但正式课程入口不再调用。

## 2. 本轮已实现

### 2.1 课程中心

- 六要素主线直接进入原生 OpenMAIC 课堂；
- 课程中心不再渲染旧固定对话工作台；
- 正式案例区明确显示“多轮原生课堂”；
- 主线未完成时便利蜂显示“待解锁”；
- 客观题全部答对后记录单元完成，并解锁便利蜂；
- 审校中的案例没有可点击课堂入口；
- 项目练习继续与正式案例物理分区。

### 2.2 原生完成规则

主线和当前试学案例使用：

```text
预生成课堂场景
→ OpenMAIC 原生互动
→ 客观题全部答对
→ 原生重试
→ 记录本机试学完成
→ 返回课程目录
```

答错进入完成页时，页面显示当前客观题正确数，并返回首个未通过测验。
开放题不参与“全部客观题答对”的解锁判断。

| 用途 | 课堂 ID | 场景 | 内容 SHA-256 | 状态 |

| 六要素主线 | `jxg-bm-mainline-six-elements-coffee-v1` | 9 | `da4afdc067b070cb88ee371eb9229e442b029f5a7f6513f5e34ba65fb8f94493` | 内部试学 |

```text

```

生产构建会把这些资产复制进 standalone 运行包。服务端先读取运行时课堂数据，
不存在时再读取只读发布资产。

### 2.4 课堂切换修复

[KNOWN, HIGH] 浏览器真实路径发现：从已完成主线返回目录再进入便利蜂时，
URL 已改变但播放器仍显示上一课堂。原因是 `/classroom/[id]` 的 SPA 路由复用了
Zustand 状态，本地存储未命中时旧课堂又阻止了服务端回退。

修复后，加载不同课堂 ID 时先清空旧课堂状态，再读取目标课堂。已增加回归测试，
并用“主线完成页 → 课程目录 → 便利蜂课堂”真实路径确认目标课堂正确加载。

## 4. 当前边界

[KNOWN, HIGH] 这是 Gate 2 的本机试学切片，不是正式 Gate 2 通过。

尚未满足正式使用的条件：

- 完成状态仍保存在浏览器 `localStorage`，不是服务端权威状态；
- 未登录用户可直接访问已知课堂 URL；
- 未实现跨设备恢复、双标签页幂等和服务端案例解锁；
- 便利蜂尚未取得具名 SME 审校批准；
- 当前 standalone 加载到 `0 LLM Provider`；预生成课堂可浏览，但实时 Agent 对话
  不可用，学员端只显示不含内部信息的重试提示；
- 生鲜零售及其余案例尚无可发布的多轮原生课程包；
- 花名与企业微信登录、PostgreSQL、关系权限和生产审计尚未实现；
- 尚未完成 1000 人容量、峰值、备份恢复和故障演练。

因此当前发布判断为：

```text
ALLOW：本机产品审阅、内部试学、课程内容审校。
BLOCK：外部正式学员、1000 人发布、正式评价与管理报表。
```

服务端 LLM Provider，并验证模型探测、超时、限费、脱敏、审计和失败重试。
