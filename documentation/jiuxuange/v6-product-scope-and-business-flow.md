# 九轩阁 MAIC V6 产品范围与业务流

版本：`6.0.0-rc`

状态：Gate 0 冻结候选

## 1. 产品目标

V6 将现有“课程入口 + 本机课堂 + L0 测评”升级为可服务首批 1000 名真实学员的正式教学产品。

它需要完成三种学习任务：

1. 通过 OpenMAIC 正式课堂学习六要素；
2. 通过逐级解锁案例完成公共案例迁移；
3. 通过真实项目卡完成个人研习、小组共建和个人迁移测评。

V6 不以“页面数量”或“聊天次数”为成功标准。正式成功事件是：

```text
真实学员被正确识别
→ 进入被授权课程与项目
→ 完成主线原生互动
→ 解锁并进入对应案例课堂
→ 围绕冻结项目卡开展私有或共享讨论
→ 形成个人笔记或项目记录
→ 独立完成六题个人项目测试
→ 获得可追溯、非数字的 AI 评价
→ 换设备后能够继续
```

## 2. 学员信息架构

```text
我的课程
├── 商业模式大课
│   ├── 案例学习路径
│   ├── 当前案例
│   └── 学习进度
│
├── 我的项目
│   ├── 项目卡
│   ├── 个人研习
│   ├── 小组讨论
│   ├── 个人项目测试
│   └── 项目档案
│
├── 我的笔记
│   ├── 课程笔记
│   ├── 案例笔记
│   ├── 项目个人思考
│   └── 待解决问题
│
└── 自由学习
    └── 保留已确认的文档生成与课堂播放体验
```

## 3. 案例学习主路径

```text
登录
→ 查看已报名课程
→ 进入商业模式课程中心
→ 进入当前开放案例
→ 播放独立预生成 OpenMAIC 课堂
→ 完成 required 原生互动
→ 客观题错误时原生重试
→ 全部客观题答对
→ 服务端记录案例完成
→ 解锁下一个案例
```

案例完成只表示：

> 学员完成了规定内容和互动。

它不自动表示：

- 已经掌握；
- 形成正式能力等级；
- 可以获得数字分数；
- 可以跳过个人项目测试。

## 4. 顺序解锁规则

```text
咖啡店案例初始开放
→ 完成咖啡店案例
→ 解锁便利蜂
→ 完成便利蜂
→ 解锁生鲜零售
→ 继续按课程配置依次开放
```

每个案例使用独立课程包、课堂实例和进度记录。前序完成只解决学习顺序，课程包仍须处于可发布状态并通过内容审校。

单张案例卡、单轮聊天或项目卡讨论都不能替代正式案例课堂。

## 5. 项目卡创建与发布

```text
教务创建项目
→ 指定案主
→ 案主以学员身份在学员端填写项目卡草稿
→ 上传企业材料
→ 为字段和材料设置 allow/mask/block
→ 区分事实、判断、假设和未知项
→ 案主预览模型可见上下文
→ 案主确认
→ 教务或授权审核人发布项目卡版本
→ 绑定班级和项目组
```

项目卡状态：

```text
draft
→ owner_confirmed
→ published
→ superseded
→ archived
```

发布后不得原地修改。任何内容变化都创建新版本。

首发允许教务在后台批量导入项目卡草稿，但导入只替代录入动作，不替代案主责任：

```text
教务后台导入
→ 标记 admin_import 与 import_ref
→ 项目卡保持 draft / pending owner confirmation
→ 案主学员在学员端核对并确认
→ 授权审核人发布
```

后台导入的数据未经案主确认时，不得进入正式测试、Agent 项目事实上下文或课程结论。

## 6. 个人研习

```text
进入项目空间
→ 选择个人研习
→ 创建或恢复私有讨论线程
→ 加载当前课程概念和冻结项目卡版本
→ 与一个 Agent 角色讨论
→ Agent 区分事实、通识和假设
→ 系统生成个人笔记草稿
→ 学员编辑并保存到“我的笔记”
```

V6 首发规则：

- 一个讨论回合只由一个 Agent 回答；
- 不做多个 Agent 同时发言；
- 原始对话默认私有；
- 教练是否可见由明确授权决定，不默认开放；
- 个人研习不产生正式分数。

## 7. 小组讨论

```text
进入项目空间
→ 选择小组讨论
→ 检查当前有效 group_membership
→ 进入该项目、课程和小组的共享线程
→ 小组成员与项目讨论 Agent 对话
→ 形成讨论摘要、观点、假设和待验证问题草稿
→ 小组成员明确确认
→ 沉淀到项目档案
```

V6 首发提供共享持久化线程，不包含多人实时文档编辑、在线光标或多 Agent 同时发言。

小组讨论的原始消息与项目档案记录分开保存。删除或更正项目记录，不得改写原始对话。

## 9. 个人项目测试

### 9.1 创建与发布

```text
教研配置六道开放题
→ 绑定课程目标
→ 绑定项目 `project_id`
→ 绑定项目卡版本
→ 冻结题目集和量表版本
→ 审核发布
→ 指定项目组可见
```

### 9.2 学员作答

```text
进入个人项目测试
→ 查看冻结项目卡和必要课程概念
→ 独立回答六题
→ 自动保存草稿
→ 正式提交第一次
→ 生成方向反馈
→ 学员修订
→ 正式提交第二次
→ 锁定答案
→ 异步生成最终评价
```

限制：

- assignment、session 与项目卡的 `project_id` 必须相同；
- session 固定保存 `project_card_version_id`，项目卡更新不改写历史测评；
- 测试页不提供实时 Agent 帮答；
- 不向评价模型传入个人研习和小组讨论历史；
- 其他组员看不到个人答案；
- 提交次数固定为两次；
- AI 任务失败不回滚提交；
- AI 任务重试不产生重复评价。

### 9.3 评价输出

评价六个维度：

```text
概念应用
项目针对性
事实与假设
因果与逻辑
方案与取舍
验证意识
```

每个维度只使用：

```text
充分展示
部分展示
尚未展示
```

评价报告必须引用具体答案片段和项目卡事实，不显示数字总分，不进行人格、潜力、晋级或淘汰判断。

## 10. 角色与权限

全局角色：

```text
learner
coach
academic_admin
curriculum_researcher
system_admin
```

项目关系角色：

```text
target_owner
team_member
team_leader
reviewer
observer
```

权限判断采用：

```text
全局角色
+ 当前班级关系
+ 当前小组关系
+ 当前项目关系
+ 数据敏感级别
+ 资源状态
```

“案主/标的主”不是永久全局角色。

## 11. 首发内容边界

| 内容 | V6 首发状态 |
|---|---|
| 咖啡店六要素导入案例 | 必须完成原生完成规则改造和 SME 审核 |
| 便利蜂 | SME 审核后发布 |
| 生鲜零售 | SME 审核后发布 |
| SHEIN | 审校中，不进入首发 |
| 花西子 | 审校中，不进入首发 |
| 整车货运平台 | 审校中，不进入首发 |
| 智能汽车 | 审校中，不进入首发 |
| 麦客思项目卡 | 开发案例；案主未确认前不作为正式企业事实 |
| 真实项目卡 | 由首批案主学员在学员端填写和确认；后台导入仅作兜底 |

## 12. 验收场景

1. 同组两名学员看到同一已发布项目卡和小组讨论，个人研习互不可见。
2. 非同组学员访问项目卡、讨论或测评时返回统一拒绝结果，不泄露资源是否存在。
3. 案主发布 V2 后，V1 会话、笔记和测评仍显示 V1，不能引用 V2 新事实。
4. 学员第一次提交后 AI 超时，答案和机会保持正确，后台重试后只生成一份评价。
5. 学员换设备登录后恢复当前课程、项目对话、笔记草稿和测评草稿。
6. 小组成员退出后，历史署名保留，但不能访问退出后新增的敏感项目内容。
7. `block` 字段的 canary 不得出现在模型输入、日志、评价、笔记草稿和导出中。
8. 未审核案例无法通过直接 URL、接口或旧缓存进入正式课堂。
