# 九轩阁学习闭环设计任务交接书

交接日期：2026-07-20  
用途：开启新 Codex 对话后直接继续，不从头回忆  
状态：当前事实冻结 + 下一任务定义，不代表后续方案已经实现

## 1. 当前已经确认的产品本体

- [KNOWN, HIGH] 一门课对应一条长期、可断点恢复的统一学习会话。
- [KNOWN, HIGH] 四个 Agent 是教学动作的人格视图，共享同一 PBL 状态，不是四条聊天线程。
- [KNOWN, HIGH] 学员不手动选择六关，进度由 PBL milestone/microtask 推导。
- [KNOWN, HIGH] LLM 负责表达，代码和证据决定状态迁移。
- [KNOWN, HIGH] 正式数字评分继续关闭。
- [KNOWN, HIGH] 测评不属于导学，本轮学习闭环不加入六道开放题。
- [KNOWN, HIGH] “不知道”和非标准回答不得阻塞课程，但必须记录为 `assisted`，不能冒充自主证据。

## 2. 当前要设计和跑通的学习闭环

```text
进入同一课程会话
→ 保存教学前初始判断
→ 必知必会短讲授
→ 便利蜂事实观察
→ 学员独立形成判断
→ 解锁课程解释并比较
→ 生鲜零售新情境迁移
→ 修正判断
→ 生成非分数反馈
→ 退出并恢复同一会话
```

[INFERRED, HIGH] 闭环必须同时包含学习动作、学习效果和证据数据三层；只把页面依次点完不算学习闭环。

## 3. 学员视角现状审计

| 节点 | 当前状态 | 学员实际体验 | 关键缺口 |
|---|---|---|---|
| 进入同一课程会话 | 部分成立 | 点击课程直接进入工作台，旧会话可在本浏览器恢复 | 仍是 IndexedDB 和本地 learnerId，不能跨设备 |
| 保存教学前初始判断 | 未实现 | V4 首屏已经先讲授，再提问题 | 无真正 `pre_instruction` 基线，无法证明教学前后变化 |
| 必知必会短讲授 | 已实现 | 教授先给最小概念片段，再问一个问题 | 文本尚未经过教授人工审校 |
| 便利蜂事实观察 | 部分实现 | 学长给出便利蜂概述并提问 | 不是正式 3-5 条事实卡，事实 ID 与来源没有对学员形成清晰观察对象 |
| 学员独立形成判断 | 部分实现 | 学员可以在对话中回答 | 没有独立 `commit` 状态，回答尚不能稳定冻结为“解锁前判断” |
| 解锁课程解释并比较 | 未实现 | 当前导学不会进入明确的 unlock/compare 体验 | 锁定解释、解锁条件、比较问题和差异证据均未接入该链路 |
| 生鲜零售新情境迁移 | 未实现 | 当前导学不会紧接着进入生鲜新情境 | 生鲜事实包尚未加工为本闭环需要的最小披露任务 |
| 修正判断 | 未实现 | 当前第三个导学问题只是六要素连接 | 没有 before/after/reason 的结构化修正对象 |
| 非分数反馈 | 未实现 | 课程后部有回顾设计，但本闭环无即时反馈 | 反馈模板、证据引用和“自主/提示/辅助”区分未接入 |
| 退出并恢复 | 部分成立 | 本浏览器刷新可恢复课程会话 | 尚未验证闭环所有中间节点；无服务端身份和跨设备恢复 |

### 审计结论

- [KNOWN, HIGH] 当前不是完整学习闭环，而是“导学首段 + 便利蜂入口”的垂直切片。
- [INFERRED, HIGH] 最大业务断层位于“便利蜂回答”之后：没有独立承诺、分析解锁、跨案例迁移和判断修正。
- [INFERRED, HIGH] 最大测量断层位于第一步：教学先于基线，导致无法比较真实的认知变化。

## 4. 新对话必须完成的设计产物

### 4.1 十节点产品合同

每个节点都必须明确以下字段，不得只写流程名称：

```yaml
node_id:
learner_goal:
entry_condition:
learner_visible_experience:
primary_agent:
teaching_action:
input_data:
allowed_knowledge:
forbidden_knowledge:
learner_output:
evidence_output:
state_event:
exit_condition:
non_blocking_fallback:
resume_behavior:
failure_state:
```

### 4.2 Agent 分工

建议起点，待新对话逐节点校验：

| Agent | 主要动作 | 不得做 |
|---|---|---|
| 教授 | 初始判断提问、概念短讲授、概念边界校准 | 不替学员形成案例结论 |
| 学长 | 带学员观察事实、把概念放回案例和新情境 | 不把作者分析当事实 |
| 神秘角色 | 提出反例、扮演不同利益相关者、挑战判断边界 | 不泄露标准答案和评分结构 |
| 成长反馈官 | 回放前后判断、区分自主/提示/辅助、生成下一步建议 | 不生成未经校准的数字分数 |

### 4.3 业务架构

新设计至少包含：

```text
课程入口/会话恢复
→ 学习导演
→ PBL 状态机
→ 课程知识服务
→ 案例披露服务
→ 证据判定服务
→ 反馈生成服务
→ 事件账本/会话快照
```

必须标明：LLM 在哪一层、状态决定权在哪一层、锁定分析由谁控制、故障时由谁降级。

### 4.4 数据架构

新设计至少区分：

1. `CourseKnowledgeSection`：主教材核验片段。
2. `CaseFact`：学员可见案例事实。
3. `LockedAnalysis`：提交前不可见的课程解释或作者判断。
4. `LearnerClaim`：学员在某一节点形成的原始判断。
5. `EvidenceDecision`：自主、提示、辅助、泄露、无依据。
6. `JudgmentRevision`：before、after、reason、factIds。
7. `LearningFeedback`：只引用证据的非分数反馈。
8. `LearningEvent`：节点、消息、提示、模型、课程包和时间。
9. `SessionSnapshot`：当前节点、下一动作、未完成状态。

必须画出读写方向和可见范围，禁止把 `LockedAnalysis`、教练判断或未核验事实送入学员侧 Prompt。

### 4.5 学员视角跑通检查

逐节点用同一个模拟学员回答以下问题：

- 我现在为什么要做这一步？
- 我看到了哪些必要信息？
- 系统现在只要求我做什么？
- 我回答“不知道”会发生什么？
- 我回答后为什么能进入下一步？
- 我能否看见不该提前看见的解释？
- 退出后回来，系统是否知道我刚才做到哪里？

任何节点无法用一句话回答，视为产品逻辑断层。

## 5. 第一轮结果定义

### A. 学习闭环成立

- 教学前判断已保存。
- 便利蜂阶段留下独立案例判断。
- 生鲜新情境中至少出现一条自主的“事实 → 关系变化 → 可能结果”表达。
- 学员保存了一次 before/after/reason 修正。
- 最终反馈能回到原始消息和事实。
- 刷新或退出后可恢复。

### B. 流程闭环成立，学习效果未证明

- 学员走完全部节点，但关键迁移依赖 `assisted`。
- 反馈只能写“完成并获得支架”，不得宣称“已经掌握”。

### C. 闭环未成立

- 出现状态卡死、重复追问、提前泄露、证据丢失或恢复失败中的任一项。

## 6. 新对话的推荐执行顺序

1. 先绘制十节点学员旅程，不改代码。
2. 为每个节点填写产品合同。
3. 绘制业务系统架构图和数据架构图。
4. 用三类模拟学员做纸面红队：自主表达、持续不知道、套话索要答案。
5. 找出逻辑断层，冻结 V5 设计版本。
6. 建立闭环测试集，再进入实现。
