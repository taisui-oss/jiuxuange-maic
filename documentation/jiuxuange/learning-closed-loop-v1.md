# 商业模式大课学习闭环定义 V1

状态：**提案，待产品确认**  
定义日期：2026-07-20  
适用课程包：`4.0.0-learning-first-orientation` 之后的新版本  
不改变当前 V4 代码与已保存会话

## 1. 什么叫闭环

[INFERRED, HIGH] 闭环不是“页面都能点完”，也不是“学员回答了所有问题”。一个学习闭环必须同时完成三件事：

1. **学习动作闭环**：学员从初始判断出发，经过讲授、案例观察、挑战、修正和迁移。
2. **学习效果闭环**：系统能比较教学前后判断，并观察学员能否把概念迁移到未见过的情境。
3. **证据数据闭环**：每个结论都能回到原始消息、案例事实、提示等级、课程包版本和状态事件。

[INFERRED, HIGH] 三者缺一时只能称为“流程跑通”，不能称为学习闭环。

## 2. 第一轮闭环的范围

[INFERRED, HIGH] 第一轮不跑完整六关，也不加入个人测评。先用一个概念单元证明学习机制成立，再复制到六关。

本轮范围：

```text
进入课程
→ 教学前初始判断
→ 必知必会短讲授
→ 便利蜂固定案例观察
→ 学员形成案例判断
→ 解锁课程解释并比较
→ 生鲜零售新情境迁移
→ 学员修正判断
→ 非分数学习反馈
→ 退出并恢复同一会话
```

### 为什么使用两个案例

- [KNOWN, HIGH] 便利蜂已经作为 V4 固定导学案例进入课程包。
- [INFERRED, HIGH] 如果教学和结果检查使用同一个案例，只能证明学员记住了刚才的解释，不能证明发生迁移。
- [INFERRED, HIGH] 生鲜零售对比可作为未见情境，只提供事实，不提供作者结论；它属于学习练习，不属于正式测评。
- [KNOWN, HIGH] 真实个人项目事实目前没有稳定核验入口，因此不能作为第一轮闭环的硬性前置条件。

## 3. 闭环包含的九个节点

| 节点 | 系统动作 | 学员可见产出 | 后台证据 | 推进规则 |
|---|---|---|---|---|
| 1. 进入 | 恢复或创建同一课程会话 | 当前任务与唯一下一问 | 会话键、课程包版本 | 不要求先提交案例 |
| 2. 初始判断 | 在讲授前提出一个边界明确的问题 | 学员原始判断 | 原文、时间、`pre_instruction` | 不评价对错 |
| 3. 必知必会 | 教授给出最小概念片段 | 概念解释 + 一个问题 | 知识片段 ID、来源 | 不知道可辅助推进 |
| 4. 案例观察 | 披露便利蜂 3-5 条事实 | 案例观察卡 | 事实 ID、页码、可见范围 | 不披露作者分析 |
| 5. 独立判断 | 要求学员说明变化的角色、关系或决策权 | 一段案例判断 | 原文、事实引用、提示等级 | 无标准措辞要求 |
| 6. 比较修正 | 解锁少量课程解释，要求比较 | 原判断与课程解释的差异 | `commit`、`unlock`、差异点 | 提交判断后才能解锁 |
| 7. 新情境迁移 | 披露生鲜零售新事实 | 一个未见情境问题 | 新案例事实 ID | 不复用便利蜂答案模板 |
| 8. 判断修正 | 要求学员说清前后变化及依据 | 修正后判断 | before、after、reason | assisted 可完成流程但不算自主迁移 |
| 9. 反馈与恢复 | 生成非分数反馈并保存 | 学到了什么、哪里仍需支架、下一步 | 证据回放、会话快照 | 刷新/退出后可恢复 |

## 4. 结果如何定义

### 4.1 三类结果，不用一个“通过/不通过”掩盖差异

#### A. 学习闭环成立

必须同时满足：

- 学员教学前的初始判断已保存。
- 便利蜂阶段有一条基于学员可见事实的判断。
- 生鲜新情境中，学员能形成至少一条“事实 → 关系变化 → 可能结果”的因果表达。
- 学员能指出一次前后判断变化，并给出变化依据。
- 迁移证据状态为 `autonomous` 或 `hinted`，没有 `leaked-answer`。
- 退出、刷新或重新进入后，当前节点与证据仍可恢复。

#### B. 流程闭环成立，但学习效果尚未证明

出现以下任一情况：

- 关键判断依赖 `assisted` 才完成。
- 学员完成了所有节点，但新情境只能复述概念，不能引用事实形成因果。
- 学员没有形成可解释的判断修正。

此时反馈应写“已完成本次学习过程，仍需要支架”，不得写“已经掌握”。

#### C. 闭环未成立

出现以下任一情况：

- 卡在无法继续的状态，或提示按钮与真实状态不一致。
- 案例判断提交前泄露作者分析。
- 模型超时、空输出或重复问题导致状态错误推进。
- 证据无法回到原始消息或事实 ID。
- 会话刷新后丢失节点、判断或提示等级。

## 5. 验收指标

### 产品流程

- 从课程入口到反馈页面无人工改库、无开发者操作。
- 每轮最多一个问题；连续相同问题不得超过一次。
- “不知道”不阻塞，但必须留下 `assisted` 标记。
- 所有“继续学习”按钮都对应真实可执行的状态迁移。
- 同一学员重新进入后恢复到唯一下一步。

### 学习效果

- 教学前判断必须早于任何概念解释和案例分析。
- 教学案例与迁移案例不同。
- 至少产生一条事实引用、一条因果关系和一条判断修正。
- 系统必须区分 `autonomous`、`hinted`、`assisted`、`leaked-answer` 和 `unsupported`。
- 第一轮不生成数字分数，只给证据化文字反馈。

### 数据证据

- 每个节点保存 `messageId`、`factIds`、`hintLevel`、`courseVersion`、`modelVersion` 和时间。
- 案例内容保持 `learner_fact` 与 `locked_analysis` 物理分层。
- 最终反馈中的每句话必须能链接到至少一条原始证据，或明确标为系统建议。

## 6. 第一轮测试角色

[INFERRED, HIGH] 第一轮应先用三个固定模拟学员回放，再让真人进入：

1. **能自主表达者**：能引用事实并形成因果，用于验证 A 类结果。
2. **持续说不知道者**：全程需要支架，用于验证 B 类结果和非阻塞推进。
3. **套话与索要答案者**：复述概念、要求标准答案，用于验证证据门与泄露防线。

每个角色都要完整跑到反馈和断点恢复，不能只测试单回合。

## 7. 本轮明确不包含

- 六道开放式个人成果测评。
- 正式数字评分和结业判断。
- 十小时有效时长。
- 小组项目导入和管理员报表。
- 六关全部内容覆盖。

[INFERRED, HIGH] 这些能力属于课程级完整产品闭环，但不应在单个学习单元尚未证明有效前同时加入。

## 8. 进入开发前仍需确认

1. 第一轮迁移案例是否确定为“生鲜零售行业模式对比”。
2. A 类结果是否接受 `hinted`，还是必须出现至少一条 `autonomous` 迁移证据。
3. 初始判断的问题采用通用企业情境，还是直接使用便利蜂的盲事实。
