# 证据包规范

> 原则：宁可不评，不可虚评。证据不满足规范时，明确告知缺什么、为什么需要，然后停止评定。

## 场景 A：自评定位

**要求提交 3–5 段真实 AI 对话记录**，需覆盖以下三类（每类至少一段）：

| 类型 | 要求 | 为什么需要 |
|------|------|------|
| ① 陌生领域求解 | 一段用户在自己不熟悉的领域向 AI 求解的对话 | 看请教模式的质量：是全盘吞下还是有验证动作 |
| ② 熟悉领域驱动 | 一段用户在自己擅长领域使用 AI 的对话 | 能力上限的主要证据源：先手判断、框架驭路、增量贡献都在这里显影 |
| ③ 多轮迭代任务 | 一个真实任务的完整过程，含 prompt 的修改历史 | 看迭代逻辑与递归：改 prompt 的依据是什么，前轮沉淀有没有进入后轮 |

**形式要求：**
- 原始导出，未经删改。允许脱敏（替换公司名、人名），不允许删轮次。
- 近 3 个月内的对话（能力会变化，旧证据只能说明过去）。
- 每段对话附一句话背景：这是什么任务、当时的目标是什么。

**证据不足的处理：** 只提交了一段对话 → 最多给出「初步印象 + 明确标注不构成评定」；只有类型②没有①③ → 可评但置信度封顶为「中」。

## 场景 B：龙门初审

**要求提交完整论道材料包：**

1. **思考过程帖**：完整思考过程（不是结论）——怎么拆解问题、选了哪个 skill、为什么、过程中的纠偏、洞察如何浮现
2. **prompt 迭代日志**：初版→每次调整→终版，每次调整附依据
3. **协作模式陈述**：选了什么模式、为什么不是其他、人与 AI 判断的博弈过程
4. **白纸重建**（强制，现场进行）：脱离 AI，用户把核心逻辑从头重推一遍。评定官出 2–3 个变形追问（换一个条件结论还成立吗？你的第 X 步为什么不能反过来？），看用户是否推得动。

白纸重建无法安排时，初审结论只能是「证据不足」，不能是「建议通过」。

## 场景 C：跌境诊断

要求提交：龙门初审报告或评审结果 + 论道原始材料。诊断只针对材料中确认的短板，不做泛泛建议。

## 防伪红旗清单

发现以下任一情况，在报告中明确记录红旗，且置信度自动降一级：

| 红旗 | 说明 |
|------|------|
| 通体光洁 | 全部样本无一处卡壳、失败、被推翻的假设。真实思考必有毛边；没有毛边的材料大概率是挑选或表演的 |
| 术语行为比失衡 | 心法术语（反思三问/知用合一/结构优先/划界……）密集出现，但找不到对应行为的原文 |
| 样本间断崖 | 不同样本呈现的能力档位相差两档以上——可能混入了他人对话或深度编辑 |
| 时间戳缺失/异常 | 无法确认对话时间与先后顺序 |
| 复述式先手 | "先答后问"的初判内容与该用户此前公开内容或常见 AI 输出高度雷同——先手判断可以背稿，追问变形可以拆穿（评定时补一个现场变形问题） |

红旗不等于作弊定性。红旗的作用是：降置信度、触发补充验证（现场变形追问/白纸重建）、在报告中提示人类评审重点核查。
